# Initial follower benchmarks — 2026-11-05

The offline follower is implemented and testable on Ubuntu. Its deterministic state/matching tests are substantially stronger than its current singing recognition. These measurements establish a reproducible starting point, not live-service readiness.

## Deterministic transcript scenarios

`npm run demo` evaluates eight generated transcript scenarios. Normal progression, extra chorus, skipped chorus, bridge jump, return to verse, noisy text, vocal dropout and human correction all complete their annotated transitions without false simulated triggers. Physical chorus slides are reused while logical occurrences are tracked separately. One-slide sections with identical repeated audio hold their occurrence until an explicit re-anchor; the observation cannot identify the repetition boundary.

These are authored transcript events. They validate matching, priors, state and policy; they do not establish acoustic recognition accuracy. Their programmed observation delay is visible in timing and correct-slide-time metrics.

## Matcher follow-up — 2026-11-06

The `heuristic-v2` matcher introduced on 2026-11-06 discounts common English connector errors and gaps, and permits a clearly leading expected slide to advance on three distinct exact content words. In the user's captured “What A Beautiful Name” run, a phrase at 27.686s scored 0.732 under v1 and held until 30.655s. Replaying identical observations under v2 scores it 0.971 and advances at 27.686s, 2.969s earlier. The earlier weak observations still hold. At that point the recording had no independent ground truth; the user subsequently supplied the first-two-minute annotations used below. The original v1 measurements above remain historical results.

On the same four saved, annotated audio runs, v2 preserves the bridge-jump result (5/5 transitions, zero false) and the two Amazing Grace results. The spoken extra-chorus replay improves from 10/13 matched transitions with two false/late transitions to 12/13 with one false/late transition. These are deterministic replays of existing ASR observations, not new recordings or a broad accuracy validation. Full replay details are saved locally in `artifacts/investigations/verse-transition/comparison.json`.

## Fixed-plan acoustic following — 2026-11-06

The user supplied 12 slide-start annotations for the first 120 seconds of “What A Beautiful Name,” saved in [ground truth](../data/ground-truth/what-a-beautiful-name-first-two-minutes.json). There are 11 transitions because the first slide starts selected. Only this excerpt is scored; its final annotation is not extrapolated through the rest of the song.

The planned follower aligns local acoustic letter probabilities to the current slide and its successor. The encoder receives no expected lyrics, reference timestamps or future audio. Reference annotations are read after inference. Two supported words, including a content word, confirm each transition. These tests tune the configuration and tracking code; no model weights were trained on this recording.

| Configuration | Matched | False or late | Median / p95 delay | Correct displayed time |
| --- | --- | --- | --- | --- |
| Archived Whisper tiny.en + heuristic-v2; 5s / 1.5s | 7 / 11 | 1 | 4.680s / 7.259s | 39.7% |
| Initial speech CTC + planned tracker; 5s / 1.5s | 6 / 11 | 1 | 2.537s / 9.032s | 48.5% |
| Music CTC + planned tracker v1; 5s / 1.5s | 11 / 11 | 0 | 3.165s / 4.237s | 71.3% |
| Music CTC + planned tracker v1; 1.5s / 0.5s | 11 / 11 | 0 | 2.436s / 4.953s | 77.8% |
| Music CTC + planned tracker v2; live-paced 1.5s / 0.5s | 11 / 11 | 0 | 1.918s / 2.442s | 81.9% |

The largest gain came from the [music-trained encoder](https://huggingface.co/mrfakename/w2v-bert-2.0-music-lyrics-ctc), running with dynamic int8 Linear layers on four CPU threads. Tracker v2 also revisits uncommitted acoustic frames when a later overlapping window improves their estimate, while retiring committed words' audio intervals to prevent duplicate counting. Replaying identical 1.5-second observations improves correct-slide time from 77.8% to 81.6%; a fresh run gives 81.7%, and the realtime-paced run above gives 81.9%. Timings include actual decoding cost. The live-paced run processes 120 seconds of audio in 120.439 seconds after model startup; maximum availability lag is 576ms.

Lower speech-model thresholds, pitch shifts, longer contexts, a larger speech model and a restricted-vocabulary speech recognizer were also explored. Some improved individual transitions, but the music-trained model gives the best consistent result without loosening the original two-word confirmation rule. Saved acoustic observations and experiment results remain under `artifacts/experiments/planned-following/`.

Noise and a wrong-song check produce zero slide changes. The secondary “Amazing Grace” recording shows a limit of the short context: 1.5s / 0.5s matches only 1 / 3 transitions (27.9% correct time). A 6s / 2s configuration matches 3 / 3, with 4.937s median delay and 64.9% correct time. Longer held notes require more acoustic context in this recording. These are a small development set; the successful first recording does not establish general accuracy across songs, singers or arrangements. Word-level highlights have no independent word-level timing labels.

Model revisions, settings, metrics, cue timestamps and negative controls are in [the machine-readable comparison](../data/benchmarks/planned-2026-11-06.json). The default planned mode now uses the music encoder and 1.5s / 0.5s settings. The Whisper mode retains its own defaults. No real microphone or ProPresenter instance was used.

## Reproduce

```sh
npm run setup:whisper
npm run fixtures:audio -- jump-bridge
npm run follow -- audio artifacts/synthetic-audio/jump-bridge/performance.wav \
  --mode auto --truth artifacts/synthetic-audio/jump-bridge/ground-truth.json \
  --output artifacts/reproduction/spoken --quiet

npm run fixtures:singing
npm run follow -- audio artifacts/singing-example/first-verse.wav \
  --song data/songs/amazing-grace-first-verse/song.json --mode auto \
  --truth artifacts/singing-example/ground-truth.json \
  --output artifacts/reproduction/singing --quiet
```

Decoder timing varies with CPU load. Repeat the alignment exactly using the captured spoken fixture:

```sh
npm run follow -- replay tests/fixtures/captured-spoken-bridge.json \
  --output artifacts/reproduction/captured --quiet
```

Open each report's SVG timeline to inspect ground truth, tracking and simulated output. Audio reports also contain total decode time, decode/audio ratio, maximum availability lag, model and window settings. Captured replay stores transcript-window settings so a replay does not silently use a different buffer.

## What the results establish

The matcher can resolve planned repeated sections, accept strong contradictory text, follow a measured spoken bridge jump, and yield to manual correction. The capture → transcription → buffer → matcher → simulated output path works without Windows or ProPresenter. Transcription and delay remain the practical constraints on real singing; the current models often misrecognize or drop sustained sung words. A zero-trigger result is safe abstention, not successful following.

Next accuracy experiments should hold all but one variable fixed: model, audio window/hop, input quality, phrase retention or policy thresholds. Compare clean singing with full mix, include more songs and independent timing annotations, and optimize false transitions and latency together. Real microphone hardware, ProPresenter behavior and church rehearsal conditions remain unvalidated.
